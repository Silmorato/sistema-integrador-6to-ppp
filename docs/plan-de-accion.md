# Plan De Accion

## Etapa 1: Organizacion Del Proyecto

Objetivo: entender como vamos a trabajar antes de programar.

Actividades:

- Presentar el sistema como un unico proyecto con modulos.
- Explicar Git, GitHub, commits, ramas y merge.
- Asignar un modulo a cada grupo.
- Acordar reglas de trabajo.
- Definir rutas y estructura de carpetas.

Resultado esperado:

- Todos los grupos entienden donde deben trabajar.
- Todos saben que no deben modificar carpetas de otros grupos sin avisar.

## Etapa 2: Disenio Comun Del Frontend

Objetivo: que el sistema parezca uno solo y no cuatro trabajos separados.

Actividades:

- Definir colores principales.
- Definir estructura de pantalla.
- Definir menu principal.
- Definir formato comun para formularios.
- Definir formato comun para listados o tablas.
- Definir textos y nombres de botones.

Resultado esperado:

- Todos los modulos comparten una misma interfaz visual.

## Etapa 3: Construccion Por Modulos

Objetivo: que cada grupo avance en su parte sin pisar a los demas.

Actividades:

- Cada grupo trabaja en su rama.
- Cada grupo trabaja en su carpeta.
- Cada grupo crea pantallas, formularios y listados.
- Los datos se simulan con arreglos, JSON o `localStorage`.

Resultado esperado:

- Cada modulo funciona de manera independiente dentro del sistema.

## Etapa 4: Integracion

Objetivo: unir los avances de los grupos en una version comun.

Actividades:

- Revisar que cada modulo funcione.
- Integrar cambios en la rama `develop`.
- Corregir conflictos si aparecen.
- Probar la navegacion general del sistema.

Resultado esperado:

- El sistema permite entrar al dashboard y navegar a todos los modulos.

## Etapa 5: Presentacion

Objetivo: mostrar el sistema como prototipo funcional.

Actividades:

- Preparar una demostracion por grupo.
- Explicar que problema resuelve cada modulo.
- Mostrar formularios, listados y estados.
- Explicar como usaron GitHub para trabajar en equipo.

Resultado esperado:

- Presentacion clara del sistema y del proceso de desarrollo.
